# Mapeando Requisitos que geram valor

## Engenharia de Requisitos

### Dominio do Problema
É o cliente, que tem o problema sobre seu nicho especifico de quais capacidades operacionais dessa situação

### Dominio da Solução
É o DEV que deve saber o portras do negocio e o por que existe focando nos objetivos de alto nivel

## Requisito de Transição:
Descrever os aspectos temporais e as capacidades nessesarias para migração do estado atual para uma nova solução

## Requuisito de software:
Funcionais: Especificam as funções, ações e comportamentos que o sistema está rodando

Não Funcional: Define a qualidade desse tipo de de atributo. Por exemplo a restrição que é utilizada para as propiedades operaçionais do sistema.
